# SpeedyWatch Project DOX

## Purpose and Ownership

- This project owns the SpeedyWatch Android and native iPhone apps: YouTube WebView browsers with native playback-rate controls, Android MP3/MP4 downloads, searchable caption transcripts, OpenRouter video summaries with follow-up chat, savable pre-watch question guides, and best-effort DOM ad skipping.
- Keep source, generated app artifacts, and verification evidence inside this project boundary. Do not reuse release artifacts or private configuration from sibling projects.
- `README.md` and `logo.png` are the public GitHub landing assets. Keep their feature claims, installation requirements, release metadata, and privacy disclosures aligned with the shipped app.

## Product Contracts

- Support Android 10 and newer with package name `com.speedywatch.app`.
- Load YouTube only over HTTPS in the app WebView. YouTube navigation remains in-app; unrelated links open through the current platform's external handler.
- Keep WebView file access, content access, mixed content, popup windows, and WebView debugging disabled. Do not add a JavaScript bridge.
- `app/src/main/assets/speedywatch.js` is the single controller for playback speed, adaptive caption-gap boosts, YouTube ad skipping, optional SponsorBlock segment skipping, caption-track discovery, caption-request triggering, current-time reporting, and timestamp seeking. Native code may call only its fixed methods with bounded numeric or boolean values and must not add a JavaScript bridge.
- Playback speed is bounded to 0.25x through 4x. The native controls provide common presets, 0.1x adjustments, direct decimal entry, and the fixed profiles Normal 1x, Careful 0.8x, Lecture 1.5x, and Podcast 2x. Settings persists the selected profile and custom default rate. Optional adaptive speed adds 0.5x only during gaps in active caption cues, never above 4x, and must return to the user's chosen baseline without overwriting it. The controller restores the correct current rate when YouTube replaces or resets media elements.
- While `MainActivity` is foregrounded, keep its window awake with Android's `FLAG_KEEP_SCREEN_ON`; do not poll, request a wake-lock permission, or keep the display awake after the app leaves the foreground.
- Ad skipping is always enabled and has no user-visible toggle. The shared controller must not accept a request to disable it. It removes known feed-ad DOM nodes and uses five ordered strategies derived from the local GMB blocker: `cancelPlayback()` plus delayed `playVideo()`, visible skip-button clicks, media seek-to-end, player `skipAd()`, and ad-slot parent removal. Hidden skip buttons must not short-circuit later fallbacks. Detection remains best effort because YouTube DOM and private player methods can change; this is not a network-level blocker.
- SponsorBlock community-segment skipping is a separate, optional feature that defaults off. When enabled, native code queries only `https://sponsor.ajay.app/api/skipSegments/{prefix}` with the recommended first four characters of the SHA-256 video-ID hash, requests only the enabled sponsor, self-promotion, and interaction categories, accepts only bounded `skip` segments for the exact active video ID, and sends them to the shared controller through fixed bounded methods. A skip shows a brief native-page notice with Undo; undoing returns to the segment start and suppresses that segment until playback leaves it. The integration is read-only and must not submit or vote on segments.
- The compact top toolbar uses icon-only Search, history, reload, YouTube Subs, Quiz, Download, Saved, and Settings actions. Search replaces Home as the leftmost action and opens a native field that accepts either keywords or a supported HTTPS YouTube video URL; keywords load YouTube results, while URLs are canonicalized through the shared `YouTubeUrls` parser and open the exact video in the existing WebView. A valid clipboard video URL prefills the field. Download sits immediately left of Saved, Saved uses a thin bookmark icon immediately left of Settings, and Settings remains the rightmost action. Do not restore the removed copy-URL or app-fullscreen toolbar actions unless the product requirement changes.
- Android accepts shared `text/plain` content and supported HTTPS YouTube VIEW intents in the existing `MainActivity`; iPhone uses the `SpeedyWatchShare` extension and shared app-group queue to open supported URLs in the existing app. Both paths must use the platform URL validator/canonicalizer, ignore unrelated links, and never load a non-HTTPS or non-YouTube URL into the WebView.
- Android exposes no toolbar lock action or central locked-state UI. When enabled in Settings, a single minimal open-lock icon stays fixed at the bottom-right immediately above the speed controls and remains above standard and fullscreen YouTube playback. One tap locks interaction; while locked, a transparent native full-window shield consumes background touches and the same icon changes to a closed lock. Only a continuous 1.2-second hold on that icon unlocks, with a determinate circular progress ring showing the hold. Disabling the icon in Settings removes the feature entry point. Keep this entirely native and do not add a JavaScript bridge.
- Android downloads are self-contained in the APK and offer MP3 audio plus available MP4 resolutions for an exact validated HTTPS YouTube video. When Download is tapped, it prefers the first valid video URL in the clipboard, canonicalizes official standard, short, mobile, music, Shorts, Live, embed, no-cookie, legacy `/v` and `/e`, and attribution-link variants, and falls back to the active validated video only when the clipboard has no valid video URL. The app bundles the official yt-dlp `2026.07.04` executable and youtubedl-android/FFmpeg runtime, replaces an older private executable when the bundled version changes, performs work in a cancellable foreground data-sync service, and publishes completed files through MediaStore under `Downloads/SpeedyWatch`. Standard choices remain available if metadata discovery fails, and MP4 selection is an upper resolution bound with H.264/AAC preferred for Android compatibility. Do not expose implementation-component names in app UI or download notifications. Downloads remain best effort for publicly available media because YouTube delivery interfaces and access restrictions can change; iPhone behavior is unchanged.
- Completed Android media filenames derive from the title reported by the actual yt-dlp download, not from dialog timing or placeholder metadata. Remove characters unsafe for Android display names, bound the display-name length, retain the MP3 or MP4 extension, and let MediaStore resolve duplicate names.
- Near the bottom of Settings and README, show `Brought to you by the team from ` as regular text followed by the linked, capitalized brand text `SEO Time Machines` pointing to `https://seotimemachines.com`. In Settings, the regular text remains white, only the brand text is link-styled and tappable, and the link opens through the platform's external HTTPS handler rather than the app WebView.
- The YouTube Subs modal loads timedtext JSON, filters captions case-insensitively, seeks through the fixed controller method, and closes after a timestamp selection. Summary results render common Markdown as readable native styled text. Every successful Summary One or Summary Two result exposes Copy summary, Save summary, and Share summary actions plus a bottom follow-up composer under the visible `Continue with a question` heading; the success status directs the user to ask below. Android follow-up chat renders each user turn in its own full-width dark-red bubble with 8dp internal padding, 10dp horizontal outer margins, and the same 6dp corner radius as native buttons, while AI output remains on the neutral summary surface; retain the visible `You` and `AI` labels so meaning never depends on color alone. Sharing uses the platform-native plain-text surface (`ACTION_SEND` chooser on Android and `ShareLink` sheet on iPhone) and includes the original validated HTTPS YouTube URL. Follow-up chat preserves the current modal's conversation while saved, copied, and shared content remains the original summary. Save summary persists the raw Markdown, summary type, video title, original HTTPS YouTube URL, and save timestamp in app-private storage (`saved_summaries.db` SQLite on Android and an atomically written JSON collection on iPhone). Prefer the signed track exposed by the page controller; when the mobile page omits it, use the no-key Android InnerTube client profile as an unofficial fallback and accept only HTTPS YouTube `/api/timedtext` URLs.
- The transcript reader preserves distinct manual and auto-generated caption tracks, lets the user choose among available languages/tracks, offers line and paragraph views, searches case-insensitively, copies the complete displayed transcript, and can follow current playback by highlighting and scrolling to the active entry. Selecting any entry seeks through the fixed controller method and closes the modal.
- Android automatically caches each successful initial Summary One or Summary Two result in the existing app-private SQLite store. Pressing the same Summary button again must immediately render the cached result in the summary view without another OpenRouter request when the summary type, exact saved prompt, selected model, validated source URL, and transcript identity all match; changing any of them requires a fresh generation. Follow-up chat turns are never part of the reusable cache and cached summaries do not appear in Saved unless the user explicitly taps Save summary.
- OpenRouter settings dynamically load text-output models from `https://openrouter.ai/api/v1/models`, prefer `inception/mercury-2` when available, and keep Summary One, Summary Two, and Quiz prompts editable. AI requests use the exact saved field prompt as the system instruction. Initial user messages contain only neutral source metadata and transcript data, with the selected Quiz count included as request metadata. Summary follow-ups keep that originating prompt unchanged, preserve prior user and assistant turns for the current modal, and add only the user's explicitly labeled question. Android resources and iPhone `AppSettings` own matching platform defaults; Summary One defaults to the detailed business implementation prompt, and an exact previously shipped stock Summary One value migrates to the current default without replacing user-edited text. Android generation also resolves a missing Summary One value to that resource default. Empty user-entered prompt fields are rejected. Do not add hidden output, structure, timestamp, quiz, or chat instructions to request builders. The API key field defaults to masked, exposes a short prefix/suffix check, and has an explicit visibility toggle. Persist the key only in platform-protected storage: Android Keystore AES-GCM ciphertext or iPhone Keychain. A DEBUG-only iPhone process environment key may support local tests, but keys must never be logged, exported, committed, or bundled.
- Model selection shows OpenRouter's advertised context length and normalized per-million-token prompt/completion prices, and offers Free and Long context filters without changing the saved model implicitly. Missing pricing or context metadata must render as unavailable rather than as zero.
- The Quiz action sends the active video's transcript and the selected 6, 10, 12, or 20 question count as neutral request data. The editable Quiz prompt solely controls the generated output. Save quiz and Share quiz become available after successful generation. Saving persists the raw output with a question-count label, video title, original HTTPS YouTube URL, and save timestamp in the same app-private saved-content store as summaries. Sharing uses the platform-native plain-text surface and includes that original validated URL.
- The Saved modal lists summaries and quizzes newest first, searches case-insensitively across video titles, content types, headings, and full saved text, and opens a Markdown-rendered detail view that shows the original URL. The detail view also shares the saved content and original URL through the platform-native share surface. Opening or sharing the source must validate an HTTPS YouTube host. Opening loads it in the existing WebView. Deletion requires confirmation.
- Settings exports a versioned cross-platform JSON backup containing non-secret app settings plus saved summaries and quizzes, and restores it only after bounded schema/type validation and explicit confirmation. Restore replaces the exported settings and saved-content collection only after the complete backup has parsed successfully. The OpenRouter API key, cached summaries, transient chat history, and platform-protected secrets are never exported.
- Android modal layouts keep at least 8dp of horizontal or vertical separation between adjacent text, buttons, and controls while preserving touch targets of at least 44dp.
- Android Settings checks the official `demetre19/SpeedyWatch` latest stable GitHub Release at most once per day when opened and provides explicit Check and Download buttons. Accept only numeric `vX.Y` through `vX.Y.Z.W` tags, the exact official release and `SpeedyWatch.apk` download paths, APK MIME type, positive size no greater than 256 MiB, and GitHub SHA-256 metadata. Compare version components numerically, report `SpeedyWatch is up to date` when the installed and published versions match, warn before downloading a published build that is not newer, and enqueue accepted downloads into the public Downloads folder without silently installing them.
- The Android launcher icon is an adaptive dark/red speed, play, and watch mark with a legacy fallback; the iPhone asset catalog uses the matching branded app icon.
- Public APK delivery uses GitHub Releases in `demetre19/SpeedyWatch`. Each release attaches the exact device-verified APK as `SpeedyWatch.apk`; the README's stable latest-download link must remain `https://github.com/demetre19/SpeedyWatch/releases/latest/download/SpeedyWatch.apk`. Keep the public APK below 128 MiB so the v0.15 updater can discover it; package `arm64-v8a` and `armeabi-v7a` native code, not the unused x86_64 payload.
- In this project, a user request to publish or push a completed, tested Android version to the repository includes committing and pushing its source changes, creating the matching stable GitHub Release, attaching the exact device-verified APK as `SpeedyWatch.apk`, and verifying the stable latest-download URL against the recorded SHA-256. Every release must also update every public-facing current-version reference before publishing: the README download-table row `Current public APK: vX.Y, debug-signed`, the version and version-code metadata, supported ABIs, exact SHA-256, signing status, and verification text. Read back the public README from the default GitHub branch after publishing; the release is incomplete while any of those fields names an older build. Treat a publish request as source-only only when the user explicitly says not to create or update a release.
- Until a production signing workflow is added, public APKs are debug-signed and the README and release notes must say so. Do not imply production signing or seamless signer migration.
- Keep a Samsung Galaxy APK installation guide immediately below the README download table. State that Developer Options and USB debugging are not required; cover the per-source `Allow from this source` permission, Samsung Auto Blocker as a temporary install-only exception that must be re-enabled, Play Protect scanning without recommending that it be disabled, Android 10 compatibility, and the different-signing-key remedy with an explicit app-private-data-loss warning before uninstalling an older copy.
- Public iPhone delivery is source-only in the separate `ios/` folder until an Apple-signed IPA, TestFlight, or App Store workflow exists. README download choices must distinguish the installable Android APK from the iPhone source ZIP/Xcode project, state that physical iPhone installation requires developer signing, and never imply that the source archive is directly installable.

## Build and Verification

- Use JDK 17 and the checked-in Gradle 9.4.1 wrapper. On this workstation set `JAVA_HOME=/Volumes/TheHoneyBadger/AndroidTooling/jdks/jdk-17.0.19+10/Contents/Home`, `ANDROID_HOME=/Volumes/TheHoneyBadger/AndroidTooling/android-sdk`, and `ANDROID_SDK_ROOT=$ANDROID_HOME`.
- Build the debug APK with `./gradlew --no-daemon :app:assembleDebug`.
- Install with `./gradlew --no-daemon :app:installDebug` while an emulator or phone is connected.
- Before publishing, calculate the exact APK SHA-256, update the README metadata, upload that same device-verified file without rebuilding as the GitHub Release asset, and verify the public latest-download URL resolves to byte-identical content.
- The existing `cmuxPhoneApi36` AVD is the primary local smoke-test profile. Verify that YouTube renders, direct 2.7x entry and 0.1x stepping report matching live media rates, no Skip ads control is shown and the controller always reports ads blocked, Settings loads the live OpenRouter catalog with Mercury 2 selected and exposes the masked API-key check and all three editable prompt fields, a captioned `/watch` video supports transcript search and timestamp seek with modal dismissal, Summary One and Summary Two each follow only their saved prompt, successful summaries expose Copy, Save, and Share actions plus continued question chat, Saved persists summaries and quizzes across modal/app reopen with source URLs, heading/body/type search filters correctly, source URLs reopen in the WebView, and Quiz follows only its saved prompt while receiving the selected count as request metadata.
- For sharing, transcript-reader, backup, model-guidance, playback-profile, adaptive-speed, or SponsorBlock changes, verify on `cmuxPhoneApi36` that a shared supported URL opens in the existing WebView; manual/ASR track selection, line/paragraph view, follow playback, copy, and seek-close work; export opens the JSON document creator and restore rejects invalid input before replacement; the live model catalog shows context and pricing plus both filters; profiles persist across relaunch while adaptive playback returns to its baseline; and SponsorBlock remains off by default, persists category choices, refreshes on SPA video changes, skips only the active video's enabled categories, and offers a working Undo.
- For Android Search changes, verify that the leftmost toolbar icon opens the URL-or-keywords field, a keyword query loads the corresponding YouTube results, every supported video URL family opens the exact canonical video in the existing WebView, invalid or external URLs remain in the dialog with an actionable error, and the opened video is available to YouTube Subs, summaries, Quiz, and Download.
- For Android summary-chat visual changes, verify that every user question retains its `You` label and renders in a full-width dark-red bubble with 8dp internal padding, 10dp horizontal outer margins, and a 6dp corner radius across wrapped lines, while each `AI` response remains on the neutral summary surface. - For Android summary-cache changes, generate a summary, confirm it is saved for reuse, and press the same Summary button again to verify the cached result appears immediately without another OpenRouter request. Close the modal, reopen the same video and summary type, and verify the cached result remains visible. Changing the prompt, model, source URL, transcript, or summary type must miss the cache, and follow-up chat must not alter the reusable original summary.

Copy each supported YouTube URL family while SpeedyWatch is on a different or non-video page, tap Download, verify that `Clipboard video` and the resolved formats identify the exact copied video, and verify that an invalid clipboard value falls back to the active video. Also verify a stale private yt-dlp executable is replaced by the bundled version without clearing app data.
- For Android filename changes, start a download while the dialog still shows `Checking this video...` and verify the completed MediaStore display name uses the YouTube title rather than `YouTube Video`.
- Run `node --check app/src/main/assets/speedywatch.js` after changing the shared injected controller, then build and launch the affected platform for behavioral changes.
