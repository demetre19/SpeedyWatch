# SpeedyWatch Project DOX

## Purpose and Ownership

- This project owns the maintained SpeedyWatch Android app and an archived, unmaintained historical client in `ios/`. Android is the main and only maintained product.
- Keep source, generated app artifacts, and verification evidence inside this project boundary. Do not reuse release artifacts or private configuration from sibling projects.
- `README.md` and `logo.png` are the public GitHub landing assets. Keep their feature claims, installation requirements, release metadata, and privacy disclosures aligned with the shipped Android app. The README must open with `Watch more in less time.`, present only the Android APK as current, and describe `ios/` only as archived historical source with an optional repository-owner contact path that makes no availability promise.

## Product Contracts

- Support Android 10 and newer with package name `com.speedywatch.app`.
- Android loads any strictly validated public HTTPS main-frame page in the existing WebView. Shared text, generic HTTPS VIEW intents, pasted URLs, and regular navigation use this universal browser path; recognized YouTube, Bilibili, Instagram, Vimeo, X, Facebook, SoundCloud, and MEGA URLs continue through their specialized handlers. Reject HTTP, credentials, control characters, localhost/private literal IPs, malformed URLs, and non-web schemes. Resource-only media/CDN URLs may be browsed only when the user explicitly opens them and must never be promoted from intercepted resources. MEGA remains specialized, Android-only, URL-only, and playback-only: selecting it opens named MEGA bookmarks plus the complete-link field, while bare or malformed MEGA shared URLs are rejected. A bookmark persists its bounded name, complete validated shared link, selected-node handle, playback timestamp, and update time inside one AES-GCM payload encrypted by an Android Keystore key. The complete link and its access key must never be logged, shared, summarized, exported, committed, included in verification evidence, or exposed outside app-private encrypted storage; deleting the bookmark deletes its ciphertext-backed entry, and backups exclude all MEGA bookmark data. Legacy accessless bookmarks require the matching complete link once, then upgrade to encrypted one-tap reopening.
- Keep WebView file access, content access, mixed content, popup windows, and WebView debugging disabled. Do not add a JavaScript bridge.
- `app/src/main/assets/speedywatch.js` is the fixed top-frame controller for playback speed, current-time reporting, deterministic active-media selection, native Play/Pause, bounded seek, PiP state, generic readable-page extraction, and the existing site-specific MEGA, YouTube, Facebook, and X methods. `app/src/main/assets/speedywatch-frame.js` is the separate minimal media-only companion installed at document start through AndroidX WebKit: it exits in the top frame, stays idle in frames without media, wakes on media insertion/events, and reports or polls only while media exists. Eligible embedded frames may report bounded HTML5 media/caption state and receive only the closed media-command set through `postMessage`; the top controller must cache frame state and never rescan every iframe for every message. Native continues calling only fixed top-controller methods through `evaluateJavascript`. Never add `addJavascriptInterface`, pass executable page data, expose Android privileges to page scripts, or inject the full site-specific controller into every frame. Select media deterministically: currently playing, then most recently interacted/played, then largest visible ready media. DRM/EME, canvas, inaccessible sandboxed frames, WebRTC-only, non-seekable live, and players that reject rate/control changes may remain unavailable and must report that explicitly.
- Playback speed is bounded to 0.25x through 4x. The native controls provide common presets, 0.1x adjustments, direct decimal entry, and the fixed profiles Normal 1x, Careful 0.8x, Lecture 1.5x, and Podcast 2x. Settings persists the selected profile and custom default rate. The full native speed bar can collapse to one bottom-right restore icon in portrait or landscape, and Android persists and backs up that collapsed/expanded choice. Optional adaptive speed adds 0.5x only during gaps in active YouTube caption cues, never above 4x, and must return to the user's chosen baseline without overwriting it. The controller restores the correct current rate when any page or embedded frame replaces or resets HTML5 media elements.
- While `MainActivity` is foregrounded, keep its window awake with Android's `FLAG_KEEP_SCREEN_ON`; do not poll, request a wake-lock permission, or keep the display awake after the app leaves the foreground.
- Android startup is controlled by a persisted, backed-up Settings `Start page` choice: `Resume last page` (default) restores the WebView bundle on process-death restore and, on cold start or a launcher tap on a running process killed by Android, reloads the persisted `last_page_url` — the last main-frame URL that finished loading successfully, recorded in `onPageFinished` and never backed up. `YouTube` or `X` always opens that site's home URL on cold start, process-death restore, and launcher taps on the running app. A main-frame page that failed to load (HTTP or network error) is recorded and never restored on the next launch; the app falls back to the start page or YouTube home. Shared text and VIEW intent URLs always take precedence over the start page.
- Fullscreen WebView video follows the device sensor instead of forcing landscape, so portrait media can fill a portrait-held phone while landscape media can still rotate naturally.
- Fullscreen video on any supported page clears all native chrome except the omnibutton. Element fullscreen keeps the existing custom-view path (`showFullscreenView` hides `appRoot`, and the shield overlay is brought to front so the omnibutton floats over the fullscreen view). Page-owned fullscreen — players that fill the viewport without the Fullscreen API, such as X — is detected by the shared controller's `fullscreenState()` (element fullscreen, the selected video covering ~95%×90% of the viewport, or the video inside a fixed full-viewport player container while occupying at least 20% of its area; embedded-frame media responds only to element fullscreen). Detection is sticky with hysteresis: once active, relaxed exit bounds (~80%×75% viewport, 15% container share) apply so hiding the system bars — which grows the WebView viewport — cannot flip detection back and oscillate the chrome every poll cycle (the v0.63 X flicker fix); bounds this loose would incorrectly enter fullscreen, so they are exit-only. Native polls `fullscreenState()` every 750 ms while resumed and not in PiP, entering immersive mode after two consecutive positive polls and leaving after two consecutive negatives. Entering hides the toolbar, speed controls, WatchPath strip, lock and PiP floating buttons, and system bars, and follows the device sensor; only the omnibutton remains. Back exits this immersive mode first (latching re-entry off until the page leaves fullscreen) before navigating, and PiP exit restores the immersive state rather than re-showing chrome.
