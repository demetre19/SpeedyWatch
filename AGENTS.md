# SpeedyWatch Project DOX

## Purpose and Ownership

- This project owns the SpeedyWatch Android and native iPhone apps: an Android multi-site media WebView browser and native iPhone YouTube browser with native playback-rate controls, Android MP3/MP4 downloads, searchable caption transcripts, OpenRouter video summaries with follow-up chat, savable pre-watch question guides, and best-effort YouTube DOM ad skipping.
- Keep source, generated app artifacts, and verification evidence inside this project boundary. Do not reuse release artifacts or private configuration from sibling projects.
- `README.md` and `logo.png` are the public GitHub landing assets. Keep their feature claims, installation requirements, release metadata, and privacy disclosures aligned with the shipped app.

## Product Contracts

- Support Android 10 and newer with package name `com.speedywatch.app`.
- Android loads only HTTPS main-frame pages for YouTube, Bilibili, Instagram, Vimeo, X, Facebook, and complete public MEGA folder/file links in the app WebView; unrelated or unsupported links open through the platform's external handler, and the Web search option opens Google externally. MEGA is Android-only, URL-only, and playback-only: selecting it opens the complete-link field, while bare or malformed MEGA URLs are rejected. Preserve only bounded validated MEGA access-key fragments; real or user-provided keys must never be logged, exported, persisted, or copied into source or verification evidence. Resource-only media CDN hosts must never become main-frame destinations. The iPhone app remains YouTube-only.
- Keep WebView file access, content access, mixed content, popup windows, and WebView debugging disabled. Do not add a JavaScript bridge.
- `app/src/main/assets/speedywatch.js` is the single controller for playback speed and current-time reporting on supported media elements, plus YouTube-only adaptive caption-gap boosts, ad skipping, optional SponsorBlock segment skipping, caption-track discovery, caption-request triggering, and timestamp seeking. Native code may call only its fixed methods with bounded numeric or boolean values and must not add a JavaScript bridge.
- Playback speed is bounded to 0.25x through 4x. The native controls provide common presets, 0.1x adjustments, direct decimal entry, and the fixed profiles Normal 1x, Careful 0.8x, Lecture 1.5x, and Podcast 2x. Settings persists the selected profile and custom default rate. Optional adaptive speed adds 0.5x only during gaps in active YouTube caption cues, never above 4x, and must return to the user's chosen baseline without overwriting it. The controller restores the correct current rate when a supported site replaces or resets media elements.
- While `MainActivity` is foregrounded, keep its window awake with Android's `FLAG_KEEP_SCREEN_ON`; do not poll, request a wake-lock permission, or keep the display awake after the app leaves the foreground.
- YouTube ad skipping is always enabled while YouTube is active and has no user-visible toggle. The shared controller must not accept a request to disable it. It removes known YouTube feed-ad DOM nodes and uses five ordered strategies derived from the local GMB blocker: `cancelPlayback()` plus delayed `playVideo()`, visible skip-button clicks, media seek-to-end, player `skipAd()`, and ad-slot parent removal. Hidden skip buttons must not short-circuit later fallbacks. Detection remains best effort because YouTube DOM and private player methods can change; this is not a network-level blocker. Do not run these strategies on other sites.
- SponsorBlock community-segment skipping is a separate, optional feature that defaults off. When enabled, native code queries only `https://sponsor.ajay.app/api/skipSegments/{prefix}` with the recommended first four characters of the SHA-256 video-ID hash, requests only the enabled sponsor, self-promotion, and interaction categories, accepts only bounded `skip` segments for the exact active video ID, and sends them to the shared controller through fixed bounded methods. A skip shows a brief native-page notice with Undo; undoing returns to the segment start and suppresses that segment until playback leaves it. The integration is read-only and must not submit or vote on segments.
- The compact top toolbar starts with icon-only Search followed immediately by the selected-site icon, then history, reload, Video Subs, Quiz, Download, Saved, and Settings actions. The icon-bearing site picker supports YouTube, Bilibili, Instagram, Vimeo, X, Facebook, MEGA last, and an external Web search. Search opens a native field that accepts keywords for services that support search or a strictly validated supported HTTPS media URL; selecting MEGA immediately opens a URL-only field for a complete public folder/file link. A URL opens that exact page in the existing WebView, while Web keywords open Google externally. A valid supported clipboard URL prefills the field. Download sits immediately left of Saved, Saved uses a thin bookmark icon immediately left of Settings, and Settings remains the rightmost action. Do not restore the removed copy-URL or app-fullscreen toolbar actions unless the product requirement changes.
- Android accepts shared `text/plain` content and strictly validated HTTPS VIEW intents for YouTube, Bilibili, Instagram, Vimeo, X, Facebook, and complete public MEGA folder/file links in the existing `MainActivity`; iPhone uses the `SpeedyWatchShare` extension and shared app-group queue for supported YouTube URLs. Both paths must use the platform URL validator/canonicalizer, ignore unrelated links, and never load a non-HTTPS, bare/malformed MEGA, or unsupported main-frame URL into the WebView.
- Android exposes no toolbar lock action or central locked-state UI. When enabled in Settings, a single minimal open-lock icon stays fixed at the bottom-right immediately above the speed controls and remains above standard and fullscreen YouTube playback. One tap locks interaction; while locked, a transparent native full-window shield consumes background touches and the same icon changes to a closed lock. Only a continuous 1.2-second hold on that icon unlocks. As soon as the hold begins, the icon and determinate circular progress ring grow to 200% scale and shift inward so the complete ring remains visible beyond the user's thumb; releasing or cancelling restores the compact size. Disabling the icon in Settings removes the feature entry point. Keep this entirely native and do not add a JavaScript bridge.
- Android downloads are self-contained in the APK and offer MP3 audio plus available MP4 resolutions for an exact strictly validated HTTPS media URL from YouTube, Bilibili, Instagram, Vimeo, X, or Facebook. When Download is tapped, it prefers the first valid supported media URL in the clipboard, canonicalizes supported YouTube variants, and falls back to the active validated media page only when the clipboard has no valid supported URL. The app bundles the official yt-dlp `2026.07.04` executable and youtubedl-android/FFmpeg runtime, replaces an older private executable when the bundled version changes, and publishes completed files through MediaStore under `Downloads/SpeedyWatch`. A cancellable foreground data-sync service owns a bounded FIFO queue with one active download and at most 50 waiting downloads; accepted follow-on requests show their queue position, the foreground notification shows the waiting count, cancelling affects only the current download, and the next waiting download starts automatically after success, failure, cancellation, or a bounded finalization timeout. The active-service queue continues while the UI is dismissed or backgrounded but is not persisted across force-stop, process death, reboot, or app replacement. When transfer progress reaches 100%, show an indeterminate finishing state rather than a completed progress bar; stop a finalization step that still has not returned after 10 minutes so the queue can continue. Standard choices remain available if metadata discovery fails, and MP4 selection is an upper resolution bound that prefers H.264/AAC-compatible MP4 streams without forcing a full-video recode. Each finished or failed job keeps a distinct result notification across queue runs and service recreation. Do not expose implementation-component names in app UI or download notifications. Downloads remain best effort for publicly available media because supported services' delivery interfaces and access restrictions can change; iPhone behavior is unchanged.
- Android MP3 downloads offer High (192 kbps), Standard (128 kbps), and Compact (64 kbps) choices. Settings persists Standard as the initial default, Android backups export and restore that non-secret preference, the Download dialog lists the saved default first, and each accepted queue job snapshots its selected quality so later Settings changes cannot alter waiting work.
- Completed Android media filenames derive from the title reported by the actual yt-dlp download, not from dialog timing or placeholder metadata. Remove characters unsafe for Android display names, bound the display-name length, retain the MP3 or MP4 extension, and let MediaStore resolve duplicate names.
- Near the bottom of Settings and README, show `Brought to you by the team from ` as regular text followed by the linked, capitalized brand text `SEO Time Machines` pointing to `https://seotimemachines.com`. In Settings, the regular text remains white, only the brand text is link-styled and tappable, and the link opens through the platform's external HTTPS handler rather than the app WebView.
- On Android, the Video Subs modal loads YouTube timedtext or bounded captions extracted from the active supported media page, filters captions case-insensitively, seeks through the fixed controller method where the active player supports seeking, and closes after a timestamp selection. The iPhone transcript flow remains YouTube-only. Summary results render common Markdown as readable native styled text. Every successful Summary One or Summary Two result exposes Copy summary, Save summary, and Share summary actions plus a bottom follow-up composer under the visible `Continue with a question` heading; the success status directs the user to ask below. Android follow-up chat renders each user turn in its own full-width dark-red bubble with 8dp internal padding, 10dp horizontal outer margins, and the same 6dp corner radius as native buttons, while AI output remains on the neutral summary surface; retain the visible `You` and `AI` labels so meaning never depends on color alone. Sharing uses the platform-native plain-text surface (`ACTION_SEND` chooser on Android and `ShareLink` sheet on iPhone) and includes the original validated HTTPS source URL. Follow-up chat preserves the current modal's conversation while saved, copied, and shared content remains the original summary. Save summary persists the raw Markdown, summary type, video title, original validated HTTPS source URL, and save timestamp in app-private storage (`saved_summaries.db` SQLite on Android and an atomically written JSON collection on iPhone). For YouTube, prefer the signed track exposed by the page controller; when the mobile page omits it, use the no-key Android InnerTube client profile as an unofficial fallback and accept only HTTPS YouTube `/api/timedtext` URLs.
- On Android, pressing Summary One or Summary Two captures the controller's bounded current playback time. Dismissing that modal after a cached or newly requested summary restores the captured position through the fixed seek method instead of restarting the video; a transcript-line selection remains authoritative and must not be overwritten by summary restoration.
- The transcript reader preserves distinct manual and auto-generated caption tracks, lets the user choose among available languages/tracks, offers line and paragraph views, searches case-insensitively, copies the complete displayed transcript, and can follow current playback by highlighting and scrolling to the active entry. Selecting any entry seeks through the fixed controller method and closes the modal. Android may retain a trusted page-observed YouTube `/api/timedtext` request only when its `v` parameter is the exact active 11-character video ID; navigation to a different or invalid video must clear it so a previous video's signed transcript can never be reused. For non-YouTube sites, accept only bounded inline caption data or HTTPS caption URLs and redirects on the selected site's explicit owned-host allowlist, and never send one service's cookies to another service.
- Android automatically caches each successful initial Summary One or Summary Two result in the existing app-private SQLite store. Pressing the same Summary button again must immediately render the cached result in the summary view without another OpenRouter request when the summary type, exact saved prompt, selected model, validated source URL, and transcript identity all match; changing any of them requires a fresh generation. Follow-up chat turns are never part of the reusable cache and cached summaries do not appear in Saved unless the user explicitly taps Save summary.
- Android WatchPath is available only from a loaded transcript in Video Subs. It accepts a non-empty bounded user goal and a fixed 5, 10, or 20 minute budget, sends the exact saved WatchPath prompt as the sole OpenRouter system instruction, and sends only neutral source metadata, bounded numeric caption cue ranges, transcript text, goal, and budget as user data. Parse only the strict versioned `WATCHPATH 1` response with chronological, non-overlapping, transcript-bounded segments whose combined duration does not exceed the selected budget; reject malformed routes instead of guessing. Preview selected segments and a computed `What I skipped` list before starting. During playback, a native strip immediately above the speed controls shows the active segment and Previous, Next, Undo, and Stop controls; Undo revisits the most recently skipped range, route playback stops when the source changes, and all seeks use the existing fixed controller method with source-identity guards. Successful exact-context routes may be cached privately but never enter Saved automatically. Settings and cross-platform backup own the editable non-secret WatchPath prompt.
- OpenRouter settings dynamically load text-output models from `https://openrouter.ai/api/v1/models`, prefer `inception/mercury-2` when available, and keep Summary One, Summary Two, WatchPath, and Quiz prompts editable. AI requests use the exact saved field prompt as the system instruction. Initial user messages contain only neutral source metadata and transcript data, with the selected Quiz count or WatchPath goal and time budget included as request metadata. Summary follow-ups keep that originating prompt unchanged, preserve prior user and assistant turns for the current modal, and add only the user's explicitly labeled question. Android resources and iPhone `AppSettings` own matching platform defaults; Summary One defaults to the detailed business implementation prompt, and an exact previously shipped stock Summary One value migrates to the current default without replacing user-edited text. Android generation also resolves a missing Summary One value to that resource default. Empty user-entered prompt fields are rejected. Do not add hidden output, structure, timestamp, quiz, or chat instructions to request builders. The API key field defaults to masked, exposes a short prefix/suffix check, and has an explicit visibility toggle. Persist the key only in platform-protected storage: Android Keystore AES-GCM ciphertext or iPhone Keychain. A DEBUG-only iPhone process environment key may support local tests, but keys must never be logged, exported, committed, or bundled.
- Model selection shows OpenRouter's advertised context length and normalized per-million-token prompt/completion prices, and offers Free and Long context filters without changing the saved model implicitly. Missing pricing or context metadata must render as unavailable rather than as zero.
- The Quiz action sends the active video's transcript and the selected 6, 10, 12, or 20 question count as neutral request data. The editable Quiz prompt solely controls the generated output. Save quiz and Share quiz become available after successful generation. Saving persists the raw output with a question-count label, video title, original validated HTTPS source URL, and save timestamp in the same app-private saved-content store as summaries. Sharing uses the platform-native plain-text surface and includes that original validated URL.
- The Saved modal groups summaries and quizzes with compact centered date dividers, showing `d MMM` for dates in the current year and `d MMM yyyy` for other years. Android defaults to newest first, offers Newest/Oldest ordering, and provides a searchable creator picker auto-populated from stored creator metadata with alphabetical counts and legacy `Unknown creator` entries last. Selecting a creator retains the same dated list. Free search remains case-insensitive across video titles, content types, creator names, headings, and full saved text and combines with the selected creator filter. The modal opens a Markdown-rendered detail view that shows the original URL, shares the saved content and original URL through the platform-native share surface, and requires confirmation before deletion. Opening or sharing the source must pass the current platform's HTTPS source-host validator. Opening loads an Android-supported site or iPhone YouTube source in the existing WebView.
- Settings exports a versioned cross-platform JSON backup containing non-secret app settings plus saved summaries and quizzes, and restores it only after bounded schema/type validation and explicit confirmation. Restore replaces the exported settings and saved-content collection only after the complete backup has parsed successfully. The OpenRouter API key, cached summaries, transient chat history, and platform-protected secrets are never exported.
- Android modal layouts keep at least 8dp of horizontal or vertical separation between adjacent text, buttons, and controls while preserving touch targets of at least 44dp.
- Android Settings checks the official `demetre19/SpeedyWatch` latest stable GitHub Release at most once per day when opened and provides explicit Check and Download-and-install buttons. Accept only numeric `vX.Y` through `vX.Y.Z.W` tags, the exact official release and `SpeedyWatch.apk` download paths, APK MIME type, positive size no greater than 256 MiB, and GitHub SHA-256 metadata. Compare version components numerically, report `SpeedyWatch is up to date` when the installed and published versions match, and warn before downloading a published build that is not newer. Enqueue accepted downloads into public Downloads, persist the exact DownloadManager ID plus expected version, size, and digest, and react only to the matching successful completion. Stream the downloaded APK to verify its exact size and SHA-256 before granting its DownloadManager `content://` URI to Android's installer. Track the resumed `MainActivity`; when verification completes while it remains resumed, post the installer launch through that Activity on the UI thread so no Downloads-folder step is required. If no Activity is resumed, retain the verified URI and post a user-initiated install notification. Route first-time users through Android's per-source install permission and resume the verified installer handoff when they return. Never silently install: Android's Update or Install confirmation remains required.
- The Android launcher icon is an adaptive dark/red speed, play, and watch mark with a legacy fallback; the iPhone asset catalog uses the matching branded app icon.
- Public APK delivery uses GitHub Releases in `demetre19/SpeedyWatch`. Each release attaches the exact device-verified APK as `SpeedyWatch.apk`; the README's stable latest-download link must remain `https://github.com/demetre19/SpeedyWatch/releases/latest/download/SpeedyWatch.apk`. Keep the public APK below 128 MiB so the v0.15 updater can discover it; package `arm64-v8a` and `armeabi-v7a` native code, not the unused x86_64 payload.
- In this project, a user request to publish or push a completed, tested Android version to the repository includes committing and pushing its source changes, creating the matching stable GitHub Release, attaching the exact device-verified APK as `SpeedyWatch.apk`, and verifying the stable latest-download URL against the recorded SHA-256. Every release must also update every public-facing current-version reference before publishing: the README download-table row `Current public APK: vX.Y, debug-signed`, the version and version-code metadata, supported ABIs, exact SHA-256, signing status, and verification text. Read back the public README from the default GitHub branch after publishing; the release is incomplete while any of those fields names an older build. Treat a publish request as source-only only when the user explicitly says not to create or update a release.
- Until a production signing workflow is added, public APKs are debug-signed and the README and release notes must say so. Do not imply production signing or seamless signer migration.
- Keep a Samsung Galaxy APK installation guide immediately below the README download table. State that Developer Options and USB debugging are not required; cover the per-source `Allow from this source` permission, Samsung Auto Blocker as a temporary install-only exception that must be re-enabled, Play Protect scanning without recommending that it be disabled, Android 10 compatibility, and the different-signing-key remedy with an explicit app-private-data-loss warning before uninstalling an older copy.
- Public iPhone delivery is source-only in the separate `ios/` folder until an Apple-signed IPA, TestFlight, or App Store workflow exists. README download choices must distinguish the installable Android APK from the iPhone source ZIP/Xcode project, state that physical iPhone installation requires developer signing, and never imply that the source archive is directly installable.
